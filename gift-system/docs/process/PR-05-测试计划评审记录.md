### 5.1 关键整改（针对老板指出的问题）
| 问题 | 整改措施 | 产出 |
|---|---|---|
| **覆盖率合并计算** | 改为三层分别计算 | TR-01/TR-02/TR-03 三份独立报告 |
| **用例未归档** | 建立 TC-U/TC-I/TC-S 编号体系 | `docs/process/test-cases/` 三份用例集 |
| **缺 RTM** | 建立需求↔用例双向追溯 | `RTM-001-需求追溯矩阵.md` |
### 5.2 覆盖率口径确认（整改后）
| 层级 | 覆盖范围 | 目标 | 说明 |
|---|---|---|---|
| 单元测试 | domain 层（纯函数） | 语句 100%/分支 100% | 只测领域层，不测 service/api |
| 集成测试 | service + infra + api | 语句 ≥95%/分支 ≥95% | 真实 DB，Mock 外部 |
| 系统测试 | 端到端流程 | 语句 ≥70%/分支 ≥70% | 真实 HTTP |
| **合计** | 全部代码 | 语句 100%/分支 100% | 三层叠加 |
> **口径说明**：单元测试**本就不该**覆盖 service/api 层（那是集成测试职责），因此单元测试覆盖率 25% 是**正常且正确**的。三层各自达标 + 叠加 100% 才是完整结论。
