## 1. 目的
定义本项目的软件质量保证活动，确保：
1. 过程按 CMMI L3 定义执行；
2. 工作产品符合标准与规程；
3. 偏差被及时发现并纠正。
---
## 2. 质量目标
| 编号 | 质量目标 | 度量指标 | 目标值 |
|---|---|---|---|
| Q1 | 需求完整无遗漏 | 需求覆盖率 | 100% |
| Q2 | 设计可测试 | 覆盖率可达性 | 100% 模块可测 |
| Q3 | 代码质量 | 语句覆盖率 | 100% |
| Q4 | 代码质量 | 分支覆盖率 | 100% |
| Q5 | 代码质量 | 条件覆盖率 | ≥90% |
| Q6 | 测试充分 | 用例数（单元/集成/系统） | ≥120/40/15 |
| Q7 | 缺陷控制 | 遗留缺陷 | 0 个 P0/P1 |
| Q8 | 文档完整 | 过程文档数 | ≥15 份 |
| Q9 | 可追溯 | RTM 覆盖率 | 100% |
| Q10 | 规模达标 | 500 票压测 | < 60 秒 |

### 3.2 审计检查单
#### 3.2.1 过程符合性审计
| # | 检查项 | 依据 |
|---|---|---|
| 1 | 需求是否经正式评审 | CMMI RD SP2.2 |
| 2 | 设计是否经正式评审 | CMMI TS SP2.3 |
| 3 | 测试计划是否经评审 | CMMI VER SP1.1 |
| 4 | 代码是否经走查 | CMMI VER SP2.1 |
| 5 | 测试用例是否归档编号 | CMMI VER SP3.1 |
| 6 | 需求是否可追溯到用例 | CMMI REQM SP1.4 |
| 7 | 缺陷是否记录并跟踪 | CMMI PMC SP1.1 |
| 8 | 配置项是否基线化 | CMMI CM SP1.2 |
#### 3.2.2 工作产品质量审计
| # | 检查项 | 标准 |
|---|---|---|
| 1 | 需求文档完整性 | 含角色/流程/数据/接口/非功能 |
| 2 | 设计文档一致性 | 与需求一致，无矛盾 |
| 3 | 代码规范 | 命名/注释/类型注解/异常处理 |
| 4 | 测试用例质量 | 有前置条件/步骤/预期结果 |
| 5 | 覆盖率达标 | 语句 100%/分支 100%/条件 90% |
| 6 | 文档格式规范 | 编号/版本/变更记录齐全 |

## 4. 审计计划
| 轮次 | 时机 | 审计范围 | 产出 |
|---|---|---|---|
| 第 1 轮 | 需求评审后 | 需求文档 + 评审记录 | QA-02 §1 |
| 第 2 轮 | 设计评审后 | 3 份设计文档 + 评审记录 | QA-02 §2 |
| 第 3 轮 | 编码完成后 | 代码 + 代码评审记录 | QA-02 §3 |
| 第 4 轮 | 测试完成后 | 测试报告 + 覆盖率 + 用例归档 | QA-02 §4 |
| 第 5 轮 | 交付前 | 全部交付物 | QA-02 §5 |

## 5. 不符合项管理
### 5.1 分级
| 级别 | 定义 | 处理时限 |
|---|---|---|
| 严重不符合 | 违反过程要求，影响质量目标 | 立即整改 |
| 一般不符合 | 部分偏离，不直接影响质量 | 3 天内整改 |
| 观察项 | 改进建议 | 下版本考虑 |
### 5.2 处理流程
```
发现不符合 → 记录（QA-02） → 通知责任人 → 制定整改措施
→ 整改 → SQA 验证 → 关闭
```
