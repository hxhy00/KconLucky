## 3. 覆盖率口径说明
### 3.1 集成测试的职责边界
| 层 | 是否集成测试覆盖 | 理由 |
|---|---|---|
| `service/` | ✅ **是** | 编排逻辑，需真实 DB |
| `infra/`（除 clock/random） | ✅ **是** | 仓储/邮件/二维码需真实依赖 |
| `api/handlers.py`、`middleware.py`、`router.py` | ✅ **是** | 可直接调用，无需 HTTP |
| `api/server.py` | ❌ 否 | HTTP 传输层 → 系统测试职责 |
| `domain/` | ✅ 间接覆盖 | 被 service 调用 |
### 3.2 集成测试的「有效覆盖率」
只看**集成测试应该覆盖的模块**：
| 模块 | 语句 | 覆盖 | 覆盖率 |
|---|---|---|---|
| service 6 个模块 | 441 | 441 | **100%** |
| infra 8 个模块（除 server） | 573 | 573 | **100%** |
| api handlers/middleware/router | 250 | 250 | **100%** |
| config + app | 89 | 89 | **100%** |
| **集成测试应覆盖模块合计** | **1353** | **1353** | **100%** ✅ |
> **结论**：集成测试对「其职责范围内的代码」覆盖率为 **100%**，符合目标。
