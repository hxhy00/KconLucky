## 2. 缺陷详情
### BUG-001（P1）推荐人重申 UNIQUE 冲突
- **描述**：被拒 7 天后同一邮箱重新注册时，`referrer.email` 唯一约束导致 `IntegrityError`，"7天可重申"规则无法生效。
- **根因**：设计将"重申"理解为新增记录，与邮箱唯一约束冲突。
- **修复**：重申时复用原记录，重置状态为 PENDING，作废旧令牌、签发新令牌（`update_for_resubmit` + `invalidate_by_target`）。
- **验证**：`test_register_rejected_after_7_days` 通过。
### BUG-002（P2）重复签到查询返回 None
- **描述**：已签到参会人再次扫码，`lookup()` 直接返回失败，`confirm()` 拿不到 result，前端无法展示"已于 XX 签到"。
- **根因**：`check_recipient_checkinable` 对 CHECKED_IN 一律拒绝。
- **修复**：CHECKED_IN 状态放行给 confirm 判断，返回 result 供前端展示。
- **验证**：`test_confirm_duplicate` 断言 result 非空通过。
### BUG-003（P1）路由分发参数顺序错误
- **描述**：`_dispatch` 把公开接口的 body 误传到 sid 位，导致 send-code/login 等全部 500。
- **根因**：未按处理器签名区分"需登录"与"公开"两类。
- **修复**：新增 `_invoke`，用 `inspect.signature` 判断首参是否 sid，按序组装。
- **验证**：TC-S 全部端到端场景通过。
### BUG-004（P2）静态文件路径错误
- **描述**：`STATIC_DIR` 上溯层数不足，CSS/JS/HTML 全 404。
- **根因**：`server.py` 位于 `src/kcon/api/`，到项目根需上溯 4 层，写成 3 层。
- **修复**：`PROJECT_ROOT = parent.parent.parent.parent`。
- **验证**：6 页面 + 静态资源均 200。
### BUG-005（P2）签到员登录签名不匹配
- **描述**：`checkin_staff_login(self, body)` 缺 sid 形参，经 `_invoke` 统一传参后报参数个数错。
- **根因**：该接口无鉴权但签名约定要求首参 sid。
- **修复**：补 `sid: Optional[str]` 占位参数。
- **验证**：`test_staff_login_and_checkin` 通过。
### BUG-006（P1）换审批员缺口（本次客户质询发现）
- **描述**：需求与 PR-03 承诺"更换审批员走独立功能"，但代码仅有 DB 方法，无 HTTP 接口；且换人后原审批员的待用审批令牌不作废，存在离职人员凭旧邮件链接继续审批的安全隐患。
- **根因**：编码阶段遗漏接口实现与令牌失效处理；此前验收报告误标"通过"。
- **修复**：
  1. `ChannelService.replace_approver()`：停用旧人→新建→作废本渠道全部未使用推荐人审批令牌→为每个待审批推荐人重签新令牌并发 M-02 给新审批员→发 M-01 通知；
  2. 新增 `POST /api/admin/approver/replace` 接口 + 路由；
  3. `TokenRepo.invalidate_by_owner()` 按归属者批量作废。
- **验证**：集成 9 + API 3 + 系统 1（TC-S-016）共 13 用例通过；channel_service 覆盖率维持 100%。
- **过程纠正**：本缺陷暴露出"变更未沿需求→设计→测试全链路传播"的问题，已按 CMMI RM/CM 补做 DOC-01~05 升版与 PR-01~05 复审（见 CR-010）。
