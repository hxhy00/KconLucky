
## 3. 配置
### 3.1 环境变量
| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `KCON_SITE_URL` | 是 | `http://127.0.0.1:8848` | 站点访问地址（邮件链接用）；挂子路径时一并写上，如 `https://www.knownsec.com/kconluck2026` |
| `KCON_BASE_PATH` | 否 | 空 | 子路径部署前缀，如 `/kconluck2026`；留空表示根路径。带前缀与不带前缀的地址都会响应 |
| `KCON_DB_PATH` | 否 | `data/kcon.db` | SQLite 数据库路径 |
| `KCON_PORT` | 否 | `8848` | 监听端口 |
| `KCON_ADMIN_EMAILS` | 是（生产） | 无 | 管理员列表，逗号分隔，支持 `email` 或 `email:name`，如 `ops@example.com:张三,boss@example.com:李四`。**仅 admin 表为空时作为初始种子写入**，之后以后台「管理员账户」管理为准 |
| `KCON_SYSTEM_EMAIL` | 否 | `kcon@knownsec.com` | 系统发件人显示邮箱 |
| `KCON_SMTP_HOST` | 否 | 空 | SMTP 服务器地址；**留空则不真发信（邮件落库到出箱，/mailbox 可查看）** |
| `KCON_SMTP_PORT` | 否 | `465` | SMTP 端口（SSL） |
| `KCON_SMTP_USER` | 否 | 空 | SMTP 账号（发件邮箱） |
| `KCON_SMTP_PASSWORD` | 否 | 空 | SMTP 密码/授权码（勿写入代码库） |
| `KCON_DEMO_CODE` | 否 | `0` | 是否在接口响应里回显验证码；**生产必须为 0**，仅本地 Demo 设 1 |
### 3.2 管理员初始化
首次启动时若 `admin` 表为空，按 `KCON_ADMIN_EMAILS` 写入初始管理员（幂等，已有数据不重复播种）。之后通过管理后台「管理员账户」卡片增停删：
- 最多 3 个启用中的管理员；
- 不能停用/删除自己；
- 不能停用/删除最后一个启用管理员；
- 仅已停用的账号可删除。
> 旧库升级：`admin` 表缺 `email` 列时启动会自动 `ALTER TABLE` 补列并建部分唯一索引（仅非空 email 参与唯一约束），无需手工迁移。
### 3.3 邮件配置

**v1 默认不真发信**：`OutboxMailer` 将邮件落库到出箱，运营在 `/mailbox` 页面查看邮件并复制审批链接。

**未接 SMTP 时管理员如何登录**：接口默认不回显验证码（`KCON_DEMO_CODE=0`），请在生产服务器本地执行：

```bash
docker compose exec gift python scripts/issue_code.py --email ops@example.com
```

拿到 10 分钟有效的一次性验证码后登录。该命令只允许运维在服务器执行，不要暴露为 HTTP 接口。

**切换真实发信**（二期企业邮箱 / 腾讯企业邮）只需配置环境变量，无需改代码：
```bash
export KCON_SMTP_HOST="smtp.exmail.qq.com"
export KCON_SMTP_PORT="465"
export KCON_SMTP_USER="kcon@knownsec.com"
export KCON_SMTP_PASSWORD="授权码"        # 建议放入 systemd EnvironmentFile 或密钥管理
export KCON_SYSTEM_EMAIL="kcon@knownsec.com"
```
启动时检测到 `KCON_SMTP_HOST` 非空即自动选择 `SmtpMailer`（SMTP_SSL），否则回落出箱模式。
systemd 示例（`/etc/systemd/system/kcon.service.d/env.conf`）：
```ini
[Service]
EnvironmentFile=/etc/kcon/kcon.env
```
`/etc/kcon/kcon.env`（权限 600）：
```bash
KCON_SITE_URL=https://ticket.kcon.com
KCON_DB_PATH=/var/lib/kcon/kcon.db
KCON_ADMIN_EMAILS=ops@example.com:张三,boss@example.com:李四
KCON_SMTP_HOST=smtp.exmail.qq.com
KCON_SMTP_USER=kcon@knownsec.com
KCON_SMTP_PASSWORD=授权码
```
### 3.4 名单导出（交接下游 KconLucky）
导出已审批接收人（`recipient.status=2`）为 CSV（utf-8-sig，列：姓名,手机号,渠道来源,公司,职位,邮箱）：
```bash
cd /opt/kcon-prod
.venv/bin/python scripts/export_recipients.py \
    --db /var/lib/kcon/kcon.db \
    --out /backup/handoff/recipients_export.csv \
    --conflicts /backup/handoff/recipients_conflicts.csv
# 可选 --stdout 将 CSV 打印到标准输出
```
按手机号去重（保留 `approved_at`/`created_at` 最新一条）；缺少手机号与重复手机号的行写入冲突表，不进入导出；空邮箱允许导出（下游导入模板邮箱选填）。命令会打印摘要：审批总数、导出条数、重复/缺手机号、唯一手机号数。

## 4. 启动
### 4.1 开发/测试环境
```bash
python run.py
# 或
python -m kcon.api.server
```
### 4.2 Docker（本项目服务器采用）
服务器出网受限，镜像在本机构建后 `docker load`：

```bash
# 本机（Apple Silicon 必须指定 amd64）
docker buildx build --platform linux/amd64 -t kcon/gift:1.0 --load .
docker save kcon/gift:1.0 | gzip -1 | ssh <server> 'gunzip | docker load'
scp docker-compose.yml .env.example <server>:/root/Code/kcon-gift/
```

```bash
# 服务器
cd /root/Code/kcon-gift
cp .env.example .env      # 填 KCON_GIFT_SITE_URL 与 KCON_ADMIN_EMAILS
docker compose up -d
curl -s http://127.0.0.1:8848/healthz
```

> 对外访问需在云安全组放行 8848（或在前置 Nginx 上做 HTTPS 终止）。
> 数据持久化在 `./data/kcon.db`；升级前先备份该文件。

### 4.3 生产环境（systemd）
创建 `/etc/systemd/system/kcon.service`：
```ini
[Unit]
Description=KCon2026 Ticket System
After=network.target
[Service]
Type=simple
User=kcon
WorkingDirectory=/opt/kcon-prod
Environment="KCON_SITE_URL=https://ticket.kcon.com"
Environment="KCON_DB_PATH=/var/lib/kcon/kcon.db"
ExecStart=/opt/kcon-prod/.venv/bin/python run.py
Restart=always
RestartSec=5
[Install]
WantedBy=multi-user.target
```
启动：
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now kcon
sudo systemctl status kcon
```
### 4.4 反向代理（Nginx，HTTPS 终止）
```nginx
server {
    listen 443 ssl http2;
    server_name ticket.kcon.com;
    ssl_certificate     /etc/ssl/kcon.crt;
    ssl_certificate_key /etc/ssl/kcon.key;
    location / {
        proxy_pass http://127.0.0.1:8848;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```
### 4.5 挂在既有站点的子路径下（如 `knownsec.com/kconluck2026/`）

需要两处配合，路径必须一致：

1. 服务端设 `KCON_BASE_PATH=/kconluck2026`、`KCON_SITE_URL=https://www.knownsec.com/kconluck2026`；
2. 上级站点把该前缀反代过来（透传前缀，由本服务自行剥离）：

```nginx
location /kconluck2026/ {
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_pass http://127.0.0.1:8848/kconluck2026/;
}
```

- 页面里的静态资源与站内链接由服务端按 `KCON_BASE_PATH` 渲染，不需要 `sub_filter`；
- 带前缀、不带前缀两种地址都响应，所以上级反代即使剥掉前缀也能工作，本机直连仍可用于排障；
- 自测：`curl -I https://<入口>/kconluck2026/login` 应为 `200 text/html`。

## 5. 数据库
### 5.1 初始化
首次启动自动建表（`Database.init_schema()`）。
### 5.2 备份
```bash
# 每日备份脚本 /opt/kcon-prod/scripts/backup.sh
#!/bin/bash
DATE=$(date +%Y%m%d)
sqlite3 /var/lib/kcon/kcon.db ".backup /backup/kcon_${DATE}.db"
find /backup -name "kcon_*.db" -mtime +30 -delete
```
加入 crontab：
```
0 2 * * * /opt/kcon-prod/scripts/backup.sh
```
### 5.3 恢复
```bash
systemctl stop kcon
cp /backup/kcon_20261025.db /var/lib/kcon/kcon.db
systemctl start kcon
```

### 8.2 会议当天应急
| 场景 | 处理 |
|---|---|
| 服务无响应 | `systemctl restart kcon`，检查 journalctl |
| 数据库锁 | 检查是否有长事务，必要时重启 |
| 签到扫码失败 | 手动输入注册码（二维码上有明文） |
| 邮件发送失败 | 后台可重发；关键邮件（M-03/M-05）失败时页面提示用户 |
| 外部签到系统故障 | 不阻断本站签到，记录失败状态，事后补推 |
