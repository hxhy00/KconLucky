## 旅程总览

```
【会前 · 票务系统 gift-system】
运维 ──► 管理员 ──建渠道──► 审批员 ──发链接──► 推荐人 ──转发──► 接收人
           │                 │审批M-02        │审批M-04        │
           │                 ▼                ▼                ▼
           │              M-03 专属链接      M-05 注册码+二维码 ◄─┘
           ▼
        导出 CSV ──────────────┐（唯一交接点）
                               ▼
【会前 · 主系统 KconLucky】
超管：配映射 → 导名单（购票 + 赠票CSV）→ 设奖品 → 建工作人员账号
                               │
【现场】                        ▼
观众扫码签到 ──► 端口号 ──► 进抽奖池 ──► 操作员抽一档 ──► 大屏揭晓
                                          │撤回不在场者
                                          ▼
                       中奖者报端口号+手机号 ──► 兑奖台双因子核验 ──► 发奖
                               │
【会后】                        ▼
超管：数据清场（验密）──► 备份归档
```

## 阶段一：票务系统 · 会前赠票分发

### 旅程 1｜运维（部署者）

| 步骤 | 动作 | 系统行为 |
|---|---|---|
| 1 | 配置 `.env`（`KCON_ADMIN_EMAILS` ≤3、SMTP、`GIFT_SITE_URL`） | — |
| 2 | 启动容器 | admin 表为空时自动播种初始管理员 |
| 3 | 验证 `/login` 可访问 | 返回登录页 |

### 旅程 2｜管理员（赠票后台）

| 步骤 | 动作 | 系统行为 / 邮件 |
|---|---|---|
| 1 | `/login` 输邮箱 → 收验证码 → 登录 | 发 CODE 验证码邮件（60s 重发间隔、单日上限） |
| 2 | 新建渠道：渠道名 + 审批员姓名/邮箱 + 配额(≤500) + 单人上限(≤100) | 发 **M-01** 开通邮件给审批员 |
| 3 | 数据总览监控全局 | 渠道/推荐人/注册/签到/配额统计 |
| 4 | 邮件出箱排查 | Demo 模式下全部邮件可预览 |
| 5 | 渠道停用 / 管理员账户增停删 | 停用后该渠道全部链接立即失效 |

### 旅程 3｜渠道审批员

| 步骤 | 动作 | 系统行为 / 邮件 |
|---|---|---|
| 1 | 收 M-01 → 邮箱验证码登录渠道工作台 | — |
| 2 | 复制「推荐人注册链接」`/r/{渠道码}` → 分发给推荐人 | — |
| 3 | 收 **M-02** 待审批通知 → 点一次性审批链接（或回工作台）→ 通过/拒绝 | 通过 → 发 **M-03** 专属链接给推荐人；拒绝 → **M-03R**（7 天后可重申） |
| 4 | 工作台 15 秒轮询本渠道数据 | 推荐人数/邀请/注册/签到/配额余量 |
| 5 | （管理员操作）换审批员 | 旧审批链接全部作废，待审批单重发给新审批员 |

### 旅程 4｜推荐人（无需账号，公开页面）

| 步骤 | 动作 | 系统行为 / 邮件 |
|---|---|---|
| 1 | 打开 `/r/{渠道码}` → 填姓名/公司/部门/手机/邮箱 → 提交 | 状态=待审批；发 **M-02** 给审批员 |
| 2 | 收 M-03 → 复制专属赠票链接 `/t/{推荐人码}` → 转发同事（可多次） | — |
| 3 | 收 **M-04** 待审批通知 → 点一次性审批链接 → 通过/拒绝 | 通过 → 复核配额 → 给接收人发 **M-05**（注册码+二维码）、给自己发 **M-06** |
| 4 | 已发数达单人上限 | 链接自动失效（「赠票已发完」） |

### 旅程 5｜赠票接收人（无需账号，公开页面）

| 步骤 | 动作 | 系统行为 |
|---|---|---|
| 1 | 打开推荐人的 `/t/{推荐人码}` → 填姓名/单位/手机/邮箱 → 提交 | 状态=待审批；发 M-04 给推荐人 |
| 2 | 收 M-05：注册码 + 二维码 | 现场凭此领资料 |
| 3 | 大会当天凭注册码走主系统签到 | 见旅程 8 |

### 旅程 6｜管理员 · 赠票导出（两系统交接点）

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1 | `docker compose exec gift python scripts/export_recipients.py --db /app/data/kcon.db --out /tmp/recipients.csv` | 只导出**已审批通过**者；按手机号去重；缺手机号进冲突表 |
| 2 | 下载 CSV → 交主系统导入 | 见旅程 7 |

## 阶段二：抽奖系统 · 会前准备（KconLucky 管理端）

### 旅程 7｜超级管理员（系统准备）

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1 | `/kconluck2026/admin/` 手机号 + 密码 + 图形验证码登录 | — |
| 2 | 【设置 → 渠道来源映射】配置渠道白名单 | 渠道来源 → 权益类型 + 是否参与抽奖；**未配映射的渠道不允许进名单** |
| 3 | 【参会名单】导入正式购票名单（6 列模板，追加模式） | 权益/抽奖资格按映射自动带出 |
| 4 | 追加导入赠票 CSV（旅程 6 产物） | 同上；按手机号 upsert |
| 5 | 【奖品设置】配置奖品档位与数量 | — |
| 6 | 【设置 → 用户管理】建工作人员账号 | 岗位多选：签到台/抽奖台/兑奖台 |
| 7 | 【现场看板】核对签到二维码地址 | 与 `LAN_IP` 一致 |

## 阶段三：抽奖系统 · 现场签到

### 旅程 8｜参会观众（签到 H5，自己手机）

| 步骤 | 动作 | 系统行为 |
|---|---|---|
| 1 | 到签到台扫水牌二维码 → 打开 `/kconluck2026/sign/` | — |
| 2 | 输入完整 11 位手机号 | 命中 → 显示身份；未命中 → 提示联系工作人员 |
| 3 | 点「确认签到」 | 分配**随机端口号（不放回）**，成功页大字展示 |
| 4 | 截图 | 此时已进入抽奖池 |

### 旅程 9｜签到台工作人员

| 步骤 | 动作 | 权限边界 |
|---|---|---|
| 1 | 目视观众截图 → 统一签到表打钩 → 发胸牌 | 截图可伪造，胸牌价值低，接受此风险 |
| 2 | 管理端【参会名单】：查名单 / 手工补录嘉宾 / 权益发放 | 不能删名单、导入、抽奖、兑奖 |

## 阶段四：抽奖系统 · 现场抽奖

### 旅程 10｜主持人 / 抽奖操作员

| 步骤 | 动作 | 系统行为 |
|---|---|---|
| 1 | 控制台选场次（上午/下午） | 大屏自动同步切换 |
| 2 | 点「抽一档」 | 后台锁定此刻抽奖池，本档名额一次抽完 |
| 3 | 大屏逐个揭晓 | 端口号滚动 → 定格 + 姓名 + 公司 → 汇总页 |
| 4 | 有人不在场 → 点该位「撤回」 | 名额退回本档，再点「抽下一档」补抽 |
| 5 | 抽奖台角色 | **不能作废中奖**（作废只留给超管） |

### 旅程 11｜超级管理员（抽奖兜底）

中奖作废（名额回池重抽）——仅超管可操作。

## 阶段五：抽奖系统 · 现场兑奖

### 旅程 12｜中奖观众

凭记忆/截图到兑奖台，口头报【端口号 + 完整 11 位手机号】。

### 旅程 13｜兑奖工作人员（双因子 · 不认截图）

| 步骤 | 系统校验 | 结果 |
|---|---|---|
| 1 | 核验页输入端口号 + 手机号 | 端口号未发放 → 拦截（疑似伪造） |
| 2 | — | 手机号不匹配 → 拦截 |
| 3 | 两者匹配 → 显示姓名/公司/奖项 → 目视核对 → 点「已领取」 | 写发放日志（谁、何时、发了哪个号） |
