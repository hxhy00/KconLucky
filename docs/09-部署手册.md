# KCon 2026 签到 + 抽奖系统 · 部署手册

**适用版本**：v0.4.0
**部署方式**：Docker Compose，只用发布镜像，不构建、不改代码
**需要的东西**：一台 Linux 服务器（2G 内存以上，已装 Docker）+ 一个能 pull 到镜像的网络

> 整套系统只靠两个文件跑起来：`docker-compose.release.yml` + `.env`。
> 数据库、账号、菜单、场次、奖品档位都在镜像里内置，首次启动自动初始化。

---

## 1. 前置检查

```bash
docker version --format '{{.Server.Version}}'   # 需要 ≥ 24
docker compose version                           # 需要 v2.x
```

## 2. 三步部署

```bash
# ① 建目录
mkdir -p /opt/kcon && cd /opt/kcon

# ② 下载编排文件和配置模板
curl -fLO https://raw.githubusercontent.com/hxhy00/KconLucky/v0.4.0/docker-compose.release.yml
curl -fL -o .env https://raw.githubusercontent.com/hxhy00/KconLucky/v0.4.0/.env.release.example

# 国内服务器拉不动 GitHub 时，改用 Gitee（内容一样）
# curl -fLO https://gitee.com/hxhy00/kcon-lucky/raw/v0.4.0/docker-compose.release.yml
# curl -fL -o .env https://gitee.com/hxhy00/kcon-lucky/raw/v0.4.0/.env.release.example

# ③ 启动
docker compose -f docker-compose.release.yml up -d
```

### 启动前必须改 `.env` 的三项

| 变量 | 怎么填 |
|---|---|
| `MYSQL_ROOT_PASSWORD` | 自己定一个 16 位以上强口令，不要用 `#` 字符 |
| `TOKEN_SECRET` | 执行 `openssl rand -base64 48`，把输出整段填进去（少于 32 字节后端拒绝启动） |
| `LAN_IP` | 服务器公网 IP（或域名），签到二维码用它生成 |

其余保持默认即可：

```dotenv
WEB_PORT=80                 # 80 被占用才改；挂外层 nginx 时见第 5 节
KCON_TAG=v0.4.0
TZ=Asia/Shanghai
PUBLIC_BASE_URL=            # 上了域名 + HTTPS 再填 https://你的域名
```

## 3. 等它起来

首次启动 mysql 要跑建库建表脚本，约 1–2 分钟，期间 `health: starting` 是正常的：

```bash
watch docker compose -f docker-compose.release.yml ps
# 四个容器（mysql / redis / backend / web）全部 (healthy) 后 Ctrl+C
```

如果 `up -d` 报 `dependency failed to start: container kcon-mysql is unhealthy`，
说明还没初始化完，直接再执行一次 `up -d` 即可。

### 验证四个入口（都应是 200）

```bash
for p in / /admin/ /sign/ /screen/; do
  curl -s -o /dev/null -w "$p %{http_code}\n" "http://127.0.0.1/kconluck2026$p"
done
```

## 4. 首次登录与必做设置

地址：`http://<服务器IP>/kconluck2026/admin/`

```
初始账号：13000000000
初始密码：Kcon2026Aa.
```

登录后按顺序做四件事：

1. **改密码**：右上角头像 → 个人中心 → 修改密码。初始密码是公开的，不改等于谁都能进超管。
2. **关验证码**（现场方便）：左侧「系统管理 → 参数设置」→ 找到 `sys.account.captchaEnabled` → 改成「否」→ 保存。
3. **核对场次与奖品**：左侧「设置 → 奖品设置」，确认上午场/下午场的档位与份数。
4. **导入名单**：左侧「参会名单 → 导入」，上传 CSV（表头见系统内模板）。

> 页面地址一览
> 入口页 `http://<IP>/kconluck2026/`
> 管理端 `http://<IP>/kconluck2026/admin/`
> 抽奖大屏 `http://<IP>/kconluck2026/screen/`
> 观众签到 `http://<IP>/kconluck2026/sign/`

## 5. 挂域名 + HTTPS（可选）

### 5.1 容器侧 `.env`

```dotenv
# 外层 nginx 和本服务在同一台机器：只绑回环（推荐，最安全）
WEB_PORT=127.0.0.1:8081
# 外层 nginx 在另一台机器：改成 8081，并在防火墙只放行那台代理的 IP
# WEB_PORT=8081

LAN_IP=你的域名
PUBLIC_BASE_URL=https://你的域名
```

改完 `docker compose -f docker-compose.release.yml up -d` 让配置生效。

### 5.2 外层 nginx

`/etc/nginx/conf.d/kcon.conf`：

```nginx
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;        # Ubuntu 22.04/24.04 的 nginx 不支持独立的 "http2 on;"
    server_name 你的域名;

    ssl_certificate     /etc/letsencrypt/live/你的域名/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名/privkey.pem;

    location /kconluck2026/ {
        proxy_pass http://127.0.0.1:8081;     # 后面不能带 /，否则前缀被剥掉变全 404
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 20m;
    }

    location = / { return 302 /kconluck2026/; }
}
```

```bash
nginx -t && nginx -s reload
```

> **`Host` 和 `X-Forwarded-Proto` 必须透传**：后端靠它们做同源判定，少一个登录等 POST 会全部 403。
> 如果这层前面还有 WAF（如创宇盾），且它只发 `X-Forwarded-Ssl: on`，v0.4.0 的内置 nginx 已兼容。

## 6. 升级 / 回滚

改 `.env` 里的 `KCON_TAG` 后：

```bash
cd /opt/kcon
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

数据在命名卷里，换版本不动数据；回滚就是把 `KCON_TAG` 改回旧版本再执行上面两条。

## 7. 备份

```bash
cd /opt/kcon
set -a; . ./.env; set +a      # 不 source 的话口令是空的，会产出 0 字节假备份
docker exec -e MYSQL_PWD="$MYSQL_ROOT_PASSWORD" kcon-mysql \
  mysqldump -uroot --single-transaction kcon_lucky > backup_$(date +%Y%m%d).sql
ls -lh backup_*.sql           # 确认是几 MB，不是 0
```

恢复：

```bash
set -a; . ./.env; set +a
docker exec -i -e MYSQL_PWD="$MYSQL_ROOT_PASSWORD" kcon-mysql \
  mysql -uroot kcon_lucky < backup_20261029.sql
```

彻底重置（**含全部数据，不可恢复**）：

```bash
docker compose -f docker-compose.release.yml down -v
docker compose -f docker-compose.release.yml up -d
```

## 8. 上线前自检（推荐）

```bash
cd /opt/kcon
mkdir -p scripts
curl -fL -o scripts/preflight.sh https://gitee.com/hxhy00/kcon-lucky/raw/v0.4.0/scripts/preflight.sh
bash scripts/preflight.sh
```

只读检查，必须全绿：四个容器 healthy、四个入口 200、密钥与口令达标、超管初始密码已修改。
退出码 1 表示有阻断项，按提示处理后重跑。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 拉镜像一直失败（`ghcr.io/token` EOF / 超时） | 多重试几次；或在能访问的机器上 `docker save | gzip` 后 scp 过来 `docker load` |
| 登录 403 `Invalid CORS request` | 外层 nginx 少透传 `Host` / `X-Forwarded-Proto`；或镜像版本过低 |
| 页面 404 | 外层 nginx 的 `proxy_pass` 带了 `/`，改成不带 |
| 观众扫码打不开 | `.env` 的 `LAN_IP` / `PUBLIC_BASE_URL` 填错，改后 `up -d` |
| 并发签到返回 429 | v0.4.0 起已移除限流，不会出现；仍出现说明镜像版本旧 |
| 登录要输验证码 | 「系统管理 → 参数设置」把 `sys.account.captchaEnabled` 改「否」 |
| `docker compose up` 报缺少 TOKEN_SECRET | `.env` 没填或值不足 32 字节 |
