## 四、数据迁移功能的安全设计

恢复是不可逆操作（误操作直接丢现场数据），四道防护：

| 防护 | 实现 |
|---|---|
| 权限 | `@ss.hasRole('admin')` + `kcon:data:migrate` 双重；前端要求输入「确认恢复」四字 |
| 先备份后破坏 | 恢复前自动 `mysqldump` 存档，**存档失败即中止**，不会先破坏再补救 |
| 危险语句拦截 | 行首锚定匹配无 `IF EXISTS` 的 DROP、TRUNCATE、全表 DELETE、GRANT/用户管理、`INTO OUTFILE` 等 |
| 审计 | `@Log` 记录导出与恢复，可在操作日志追溯 |

> **为什么检测要「行首锚定」而不是扫全文**：备份里的数据行本身可能包含这些词。例如操作日志表存着某条报错信息
> 「…已拒绝执行：DROP DATABASE x」，全文扫描会把这句**数据**当成语句，结果「系统自己导出的备份自己恢复不了」。
> 这个坑已踩过并修正，只匹配行首才能区分「作为语句」和「作为数据」。
