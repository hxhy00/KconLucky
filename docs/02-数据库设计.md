# KCon 2026 签到 + 抽奖系统 · 数据库设计

**版本**：v2.0
**日期**：2026-10-12
**数据库**：MySQL 8.0
**库名**：`kcon_lucky`（新建，独立于现有 `eams` / `eams_ruoyi`）

---

## 1. 设计原则

1. **单机本地部署**，无分布式、无缓存中间件强依赖。
2. **手机号是业务主键**（唯一），端口号是抽奖/兑奖凭证（也唯一）。
3. 抽奖池**不快照存储**，每次抽奖实时按规则查询（保证「点按钮瞬间锁定」语义）。
4. 所有表带 RuoYi 标准字段（`create_by / create_time / update_by / update_time / remark`）以便融入后台。
5. 端口号分配要**不放回 + 并发安全**，用「预生成池表 + 悲观锁」实现。

## 3. 表结构详细

### 3.1 `kcon_attendee` 参会人名单

**导入必填 5 列**：姓名 / 手机号 / 渠道标识 / 票种 / 是否参与抽奖；**选填 4 列**：公司 / 邮箱 / 第几次参加 KCon / 职务·年级（缺失留空，可在管理端补录）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT | PK, AUTO | |
| `name` | VARCHAR(64) | NOT NULL | 姓名（导入列） |
| `phone` | VARCHAR(20) | **UNIQUE**, NOT NULL | 手机号（导入列，业务主键） |
| `channel` | VARCHAR(8) | NULL | **渠道标识（导入列）**；单字母票源编码 `S/T/C/H/D/G/V`，见《票源渠道对照表》，原样存储、不做枚举校验 |
| `ticket_type` | VARCHAR(32) | NULL | **票种（导入列）**；如 `散客票/早鸟票/标准票/合作渠道票/对公票/赠票/嘉宾票`，自由文本、不做枚举校验 |
| `draw_eligible` | TINYINT | NOT NULL, DEFAULT 0 | **是否参与抽奖（导入第 5 必填列，spec 006）**；`1`=是 `0`=否；票务侧显式事实，导入只有填「是」才入库为 1，留空/无法识别按 0（fail-safe）；追加导入时始终以最新导入为准覆盖；判定口径见 `specs/006-draw-only-paid-ticket/spec.md` 2.2 |
| `company` | VARCHAR(128) | NULL | 公司（选填，可后补） |
| `email` | VARCHAR(128) | NULL | 邮箱（选填，可后补） |
| `attend_count` | INT | NULL, DEFAULT NULL | 第几次参加 KCon（选填；`1`=首次，`N`=第 N 次；空=未知） |
| `position` | VARCHAR(64) | NULL | **职务/年级（选填）**；职场人填职务（`CTO`），学生填年级（`大二`），原样存储展示 |
| `phone_tail4` | CHAR(4) | INDEX | 手机号后四位（冗余，保留兼容；当前签到查询已不再使用） |
| `import_batch` | VARCHAR(32) | | 导入批次号 |
| `create_by` / `create_time` / `update_by` / `update_time` | | | RuoYi 标准字段 |

**索引**：`uk_phone(phone)`、`idx_tail4(phone_tail4)`、`idx_company(company)`、`idx_channel(channel)`、`idx_ticket_type(ticket_type)`

> - 唯一索引建在 `phone` 上，天然保证「同号去重」；追加模式用 `INSERT ... ON DUPLICATE KEY UPDATE`。
> - **导入按表头名识别列、顺序不限**；多余列（票种、购票时间、金额等）自动忽略；缺必填列直接报错。
> - `attend_count` 的取值由票务侧统计填入；缺失留 `NULL`，签到不阻塞（签到页显示为「—」或「欢迎首次/再次参加」）。
> - `position` 不拆分为「职务」「年级」两列：票务侧只提供一张表，拆列会迫使他们填两个字段；系统按单列存储、原样展示。
> - `channel` / `ticket_type` 只做分流与统计：金额、购票时间、发票需求等其余票务字段仍由票务总表管理，**不进本系统**。

### 3.2 `kcon_checkin` 签到记录

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGINT | PK, AUTO | |
| `attendee_id` | BIGINT | NOT NULL, INDEX | 关联 `kcon_attendee.id` |
| `phone` | VARCHAR(20) | **UNIQUE** | 手机号（一人一条签到记录） |
| `port_no` | INT | **UNIQUE**, NOT NULL | 分配的端口号 |
| `checkin_date` | DATE | NOT NULL, INDEX | 签到日期（支持「当日」判断） |
| `checkin_time` | DATETIME | NOT NULL | 签到时间（精确到秒） |
| `create_time` | DATETIME | | |

**索引**：`uk_phone(phone)`（防重复签到）、`uk_port(port_no)`、`idx_date(checkin_date)`

> **重复签到不变号**：`phone` 唯一，第二次签到直接读已有记录返回原 `port_no`。

### 3.3 `kcon_port_pool` 端口号池

预生成 1–65535 全部记录，分配时置为 `USED`，**天然不放回**。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `port_no` | INT | PK | 1–65535 |
| `status` | TINYINT | NOT NULL, DEFAULT 0, INDEX | 0=空闲 1=已分配 |
| `phone` | VARCHAR(20) | NULL | 分配给的手机号 |
| `used_time` | DATETIME | NULL | 分配时间 |

**分配算法（并发安全 + 不放回）**：
```sql
START TRANSACTION;
-- 随机取一个空闲端口，加行锁
SELECT port_no FROM kcon_port_pool
 WHERE status = 0
 ORDER BY RAND()
 LIMIT 1 FOR UPDATE;
UPDATE kcon_port_pool SET status = 1, phone = ?, used_time = NOW()
 WHERE port_no = ?;
COMMIT;
```
> 单机低并发场景足够；若担心 `ORDER BY RAND()` 慢，可改为「随机偏移 + 向右找第一个空闲」。

### 3.8 名单与奖品的 CRUD 约束

| 表 | 约束 |
|---|---|
| `kcon_attendee` | 新增/编辑时 `phone` 唯一校验；`channel` 为单字母自由值（可空，不做枚举校验）；`ticket_type` 为自由文本（可空，不做枚举校验）；`draw_eligible` 为 0/1（编辑弹窗开关，spec 006）；`email` 做格式校验（可空）；`attend_count` 需为 ≥1 的整数或空；`position` 为自由文本（可空，不校验）；**已签到的人员默认禁止删除**（避免签到记录悬空） |
| 名单导入 | **必填列**：姓名 / 手机号 / 渠道标识 / 票种 / 是否参与抽奖；**选填列**：公司 / 邮箱 / 第几次参加 KCon / 职务·年级；按表头名匹配（顺序不限），多余列忽略，缺必填列报错；「是否参与抽奖」只有填「是」入库为 1，留空/无法识别按 0 并单独计数提示（spec 006） |
| `kcon_prize` | 修改 `quantity` 时校验 `quantity >= drawn_count`；删除已抽过的档位需二次确认 |

## 4. 抽奖池查询（核心 SQL）

**上午场**（点按钮时刻之前已签到 且 未中奖/未领取）：
```sql
SELECT c.port_no, a.name, a.company
FROM kcon_checkin c
JOIN kcon_attendee a ON a.id = c.attendee_id
WHERE c.checkin_time <= NOW()                       -- 此刻已签到
  AND c.port_no NOT IN (
      SELECT port_no FROM kcon_winner
      WHERE status IN (0, 1)                        -- 已中奖/已领取
  )
ORDER BY RAND() LIMIT 1;
```

**下午场**（在上午场基础上，再剔除上午已中奖的人 —— 已含在 `status IN (0,1)` 中）：
```sql
SELECT c.port_no, a.name, a.company
FROM kcon_checkin c
JOIN kcon_attendee a ON a.id = c.attendee_id
WHERE c.checkin_time <= NOW()
  AND c.port_no NOT IN (
      SELECT port_no FROM kcon_winner
      WHERE status IN (0, 1)                        -- 含上午已中奖
  )
  -- 下午场额外：仅当天签到者（当日判断）
  AND c.checkin_date = CURDATE()
ORDER BY RAND() LIMIT 1;
```

> 说明：因为「上午已中奖」的记录本身就满足 `status IN (0,1)`，所以**同一条排除条件天然覆盖了「下午剔除上午中奖」**。若产品要求下午场只抽当天的人，加日期条件即可。

> **spec 006（2026-10-16）**：池口径新增「真正买票者」过滤 = `a.draw_eligible = 1` 且 `a.channel` ∉ 黑名单（默认 `G,V`，系统参数 `kcon.draw.excludeChannel`）且 `a.ticket_type` 不含黑名单关键字（默认 `赠,嘉宾,VIP,媒体,免费,邀请`，系统参数 `kcon.draw.excludeTicketKeyword`）。实现上过滤在 Java 层做（`KconDrawServiceImpl.calcPool`，唯一计算入口），因为依赖可配置关键字；`KconCheckinMapper.xml` 的 `selectAllPorts` 已改为 `join kcon_attendee` 一次带出 `channel / ticket_type / draw_eligible`。上两段 SQL 仅为基础口径示意。
