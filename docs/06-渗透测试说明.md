## 1. 系统概述

这是 KCon 2026 大会现场使用的一套**签到 + 抽奖 + 兑奖**系统，同一台服务器上还并行运行一套**赠票分发**系统。

| 子系统 | 负责什么 | 不负责什么 |
|---|---|---|
| **KconLucky**（主系统） | 现场签到、抽奖大屏、奖品与权益发放、兑奖核销、参会人名单与数据看板 | 会前赠票资格审批 |
| **赠票系统**（gift-system） | 会前「渠道 → 推荐人 → 赠票接收人」三级分发与审批、注册码邮件下发 | 现场签到（已禁用） |

两套系统**数据不互通**：赠票系统导出 CSV，由运营在主办方系统「名单导入」以追加模式人工导入，单向、手动触发。

现场流程：

1. 参会者在手机 H5 上输入手机号或手机尾号，查询到本人后点击确认，完成签到；
2. 签到成功后系统分配「寄存/兑奖端口号」，参会人凭端口号到服务台领取物料；
3. 抽奖只由管理端发起，大屏被动轮询展示，不提供任何写接口；
4. 工作人员在管理端核验身份并发放奖品/权益，所有动作留操作日志。

## 3. 架构与技术栈

```
公网 :80
 └─ nginx 1.27（容器 kcon-web，唯一公网入口）
     ├─ /kconluck2026/admin/      → Vue 2.6 + Element UI 静态产物
     ├─ /kconluck2026/sign/       → Vue 3 + Vite 静态产物
     ├─ /kconluck2026/screen/     → Vue 3 + Vite 静态产物
     ├─ /kconluck2026/prod-api/   → Spring Boot（RuoYi）后端
     └─ /kconluck2026/其余         → Python 3.12 赠票系统
```

| 组件 | 技术栈 | 备注 |
|---|---|---|
| 后端 | Spring Boot + MyBatis + Druid + JWT | 端口 8080，仅容器内网 |
| 管理端 | Vue 2.6 + Element UI（webpack 构建） | 账号密码 + 数学图形验证码 |
| 签到 H5 | Vue 3 + Vite | 匿名访问 |
| 抽奖大屏 | Vue 3 + Vite | 匿名只读轮询 |
| 赠票系统 | Python 3.12 标准库 `http.server` + SQLite | 邮箱验证码登录 |
| 数据 | MySQL 8、Redis、SQLite | 均不暴露公网 |
| 编排 | Docker Compose（5 个容器） | nginx / backend / mysql / redis / gift |

## 4. 账号与权限

**主系统**

- 管理员 `admin`（超管）+ 按岗位（`role_key`）划分的普通账号；
- 权限在**服务端**用 `@PreAuthorize` 校验；前端隐藏菜单不作为安全边界，绕过前端直接调接口应被拒绝；
- 登录接口带图形验证码（数学题），并有失败次数限制。

**赠票系统**

- 邮箱 + 验证码登录；验证码只投递给 admin 表中已登记的管理员或渠道上已登记的审批员；
- 会话令牌放在请求头 `X-Session`（不是 Cookie），会话存于进程内存；
- 角色：管理员（全局）、审批员（按渠道隔离）；
- 审批链接、注册码链接为一次性 token。

**测试账号**：主系统 `pentest_admin`（超管）、`pentest_staff`（签到台岗位），口令见 2.3；赠票系统通过已登记的管理员邮箱收验证码。

| 项 | 说明 |
|---|---|
| 主系统鉴权 | 请求头 `Authorization: Bearer <JWT>` |
| 赠票系统鉴权 | 请求头 `X-Session: <sid>` |

| 导出 | 需管理员权限，单次导出有行数上限 |

主要业务模块（接口前缀均为 `/kconluck2026/prod-api`）：参会人名单与导入导出、签到、抽奖与场次、中奖记录、奖品/权益发放、兑奖核验、操作日志、数据迁移。

## 6. 已知安全控制（请勿作为漏洞重复提交）

1. 列表接口不返回完整手机号/邮箱，属**有意脱敏**；
2. 大屏匿名接口只返回端口号、奖项、时间，**不返回姓名与手机号**，属有意设计；
3. 签到成功后**禁止修改手机号**，用于防止顶替签到；
4. 员工相关接口有岗位白名单（`StaffRoleGuard`），非授权岗位返回 403 属预期；
5. 限流只信任 nginx 写入的 `X-Real-IP`，伪造该请求头不会绕过限流；
6. 赠票系统对未知邮箱返回与已知邮箱**相同的提示，但不实际发信**，是防账号枚举设计；
7. 抽奖、清场、恢复、作废等写操作只能由管理端发起，大屏与 H5 无对应端点；
8. 旧路径 301 到 `/kconluck2026/`，目标固定，不是开放重定向；
9. 管理端导出/导入接口对文件大小、行数、字段长度有上限校验，超限返回业务错误而非 500。

## 7. 测试范围与禁止事项

### 7.1 范围内

认证与会话管理、水平/垂直越权、SQL 注入、命令注入、模板注入、XSS（存储型/反射型/DOM）、CSRF、文件上传与解析、SSRF、敏感信息泄露、限流与暴力破解、安全响应头与 TLS 配置、第三方依赖已知漏洞。

### 7.2 范围外

- `knownsec.com` 官网及其它公司资产；
- 腾讯企业邮（SMTP 投递链路）、云厂商控制台；
- 物理安全、社会工程、内部人员配合的攻击场景。

### 7.3 明确禁止（会直接影响真实活动）

- **任何破坏性操作**：清空/删除参会人、执行「清场」或「恢复」、批量删除奖品、修改管理员口令、删除容器或数据卷；
- **压测与 DoS**：这台机器只有 1.7G 内存，压力测试会直接把现场系统打挂；
- 目录爆破、暴力破解请控制在 **≤5 请求/秒**，触发 429/503 立即停止；
- 大量触发验证码邮件（企业邮箱有频率与配额限制，会波及真实业务）；
- 读取、导出、外传真实参会人个人信息（手机号、邮箱、单位、职位）；
- 在主机上修改配置、重启服务、改动数据库。
